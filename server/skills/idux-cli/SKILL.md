# IDux CLI

Query metadata extracted from the IDux source tree before proposing or changing IDux code. Match the target project's exact IDux version and prefer machine-readable output.

## Core workflow

1. Run commands from the target project's root so automatic version detection can find `node_modules/@idux/components/package.json`.
2. Confirm the selected version with `idux-cli versions`.
3. Resolve an ambiguous component with `idux-cli list <keyword> --json`.
4. Query only the API sections needed for the task.
5. List demos before loading source, then fetch only the most relevant demos.
6. Apply the result to the project, preserving its Vue, TypeScript, import, and styling conventions.
7. Load the component structure styles and the selected theme; component classes without computed IDux styles are a failed result.
8. Run the project's relevant typecheck, production build, and required viewport browser checks.
9. State which IDux version informed the answer or implementation.

Read [references/command-reference.md](references/command-reference.md) when selecting a version, constructing a query, interpreting JSON, or recovering from an error.

## Select the version deliberately

Treat the catalog's `source.version` as part of every query result.

- If the project has dependencies installed, rely on project detection and verify the version shown by `versions`.
- If the user names an exact version, pass `--idux-version <version>` on every read command.
- If dependencies are not installed, obtain an exact version from the lockfile when possible. Do not treat a semver range in `package.json` as an installed version.
- If the required catalog is missing, run `idux-cli sync <exact-version>`. Do not silently query another cached or bundled version.
- Use `idux-cli sync` without a version only when the user asks for the current npm latest data.
- Use `--idux-version bundled` only for an explicit offline or bundled-data request.

Do not mistake the CLI package version from `idux-cli --version` for the IDux component-library version.

## Discover before querying

Use `list --json` when the user's term may refer to multiple capabilities. IDux component IDs are generally kebab-case; Pro and CDK IDs are namespaced as `pro-*` and `cdk-*`. Source component names such as `IxButton` and `IxSelectPanel` are also accepted.

Do not guess between similarly named capabilities such as `select`, `selector`, `tree-select`, and `pro-tag-select`.

## Query the narrowest useful API

Prefer these commands:

```bash
idux-cli info <component> props --json
idux-cli info <component> slots --json
idux-cli info <component> events --json
idux-cli info <component> methods --json
```

Use `--api <name>` for a specific exported subcomponent. Use the exact API section name as the positional section when a task concerns a nonstandard section.

Query `all` only when the user requests a full API inventory or when several sections are genuinely required. Large components can produce substantial output.

## Use demos as implementation evidence

First list demo names and descriptions:

```bash
idux-cli demo <component> --list --json
```

Then fetch a selected demo:

```bash
idux-cli demo <component> <demo-name> --json
```

Treat demo source as version-pinned evidence, not as drop-in application code. Documentation demos can rely on global component registration, site-only styling, or simplified data. Add imports and adapt state, types, error handling, accessibility, and styling to the target project.

## Preserve the IDux visual system

Use IDux components for interactive controls and primary surfaces. Do not replace `IxButton`, `IxInput`, `IxSelect`, `IxTable`, `IxCard`, tags, pagination, dialogs, or forms with native controls plus look-alike CSS.

For the static full-theme output generated by this repository, use the structure CSS and exactly one complete official theme:

```ts
import '@idux/components/index.full.css'
import '@idux/components/default.full.css'
```

Use `dark.full.css` in place of `default.full.css` for a validated dark-theme page. Both selected files are required: `index.full.css` provides reset and component structural CSS, while the theme file provides all global and component variables. Loading only the first leaves color and background variables unresolved. Do not treat the presence of `.ix-*` classes as proof that styling works. In a browser, verify the global `--ix-color-bg` token plus component-specific variables such as `--ix-button-height-md`, `--ix-table-head-bg-color`, and `--ix-card-padding-size-md`.

Use `--ix-*` design tokens for custom layout color, typography, spacing, borders, and shadows. Apply the separate `idux-style` skill for page composition and visual rules. Check the result at 1920×1080 and 1366×768, including readable type, control size, internal table scrolling, search behavior, primary-action feedback, and the absence of page-level horizontal overflow.

## Interpret Vue APIs correctly

IDux documents Vue events as `onXxx` props. In templates, translate them to the project's established listener form, commonly `@change`, `@clear`, or `@search`; in render functions or programmatic props, retain `onChange`, `onClear`, or `onSearch`.

Use the returned slot name and slot-prop type exactly. Do not invent aliases from demo prose.

## Preserve evidence and scope

- Prefer JSON output for reasoning and automation; use human output only for quick interactive inspection.
- Use the returned `sourceUrl` when precise provenance is useful.
- Do not claim an API exists unless it appears in the selected version's query result or the target source itself.
- When adapting a demo, copy only the behavior relevant to the request.
- If a query contradicts existing project code, report the version and API difference instead of silently rewriting unrelated behavior.

## Recover safely

On a missing component or demo, use the CLI's suggestions and `list` output before changing the query. On a missing catalog, sync that exact version. If remote sync is blocked, use an existing IDux checkout with `sync <version> --source <path>`. On WSL2, pass Linux mount paths such as `/mnt/d/code/idux`.
