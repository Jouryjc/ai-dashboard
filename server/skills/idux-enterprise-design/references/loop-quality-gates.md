# Loop quality gates

## Requirement gate

- Every must capability describes actor, object, task, outcome, data mode, and permission/safety boundary where applicable.
- Styling and reversible pattern choices are not clarification blockers.

## Blueprint gate

- Every requirement maps to modules, task views, and at least one executable scenario.
- Every view declares a justified enterprise pattern, density, and responsive priorities.
- Actions declare scope, target, permission, risk, confirmation, and verifiable result.
- Existing unrelated modules and regression scenarios remain intact.

## Source and build gate

- Vue 3, exact IDux dependencies, ProLayout shell, official themes, modular runtime, no remote code, no credentials.
- Required IDux components have versioned evidence.
- All three runtime skills appear in generation evidence with valid hashes and provenance.

## Runtime gate

- Full application and required task scenarios run independently at `1920×1080` and `1366×768`.
- `862×623` embedded view keeps visible navigation/header/task content and a working content scroll owner.
- Collections expose their applicable search/filter, action, state, and overflow behavior.
- Destructive actions use contextual IDux modal confirmation and produce the asserted state change.
- Empty, no-results, loading/refresh, error, and permission states exist when required by the blueprint.

## Visual gate

- Application, module, view, action, and task surface hierarchy is stable.
- Density supports the task; typography and controls remain readable.
- Page choice matches the user task and data shape. Reject universal dashboard-card/list templates.
- IDux identity is visible without decorative CSS competing with its tokens and components.

## Repair contract

For each failure record:

```text
expected behavior + observed evidence + reproduction + responsible layer + allowed repair scope + pass condition
```

Repair in this order: deterministic asset/config restoration, constrained source repair, targeted blueprint replan, expanded IDux/pattern evidence replan. Rebuild and rerun the complete suite after every attempt. Never promote a partial pass.
