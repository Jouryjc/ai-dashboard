# 多产物生成架构

## 目标

同一个工作台支持两类边界明确的产物：

- `dashboard`：固定画布的数据大屏，由 LoopEngine 驱动分析、取数、生成、视觉检查和修复。
- `business-app`：可持续演进的多模块企业业务应用，支持任意领域的概览、列表、表单、详情、权限、状态流与定制任务，固定验收 1920×1080 与 1366×768 两档桌面视口；当前由 Vue + Vite + IDux 实现。

项目创建后锁定 `artifactKind`。后续消息、回答、回退、构建、验证、预览、导出和发布全部按该类型路由，不允许在处理中静默切换生成器。旧 `/dashboards` API 只作为兼容入口；新能力使用 `/projects`，创建时必须显式传入类型。

## 分层

```mermaid
flowchart LR
  U["用户需求"] --> I["意图识别与类型确认"]
  I -->|"dashboard"| D["LoopEngine 大屏流水线"]
  I -->|"business-app"| P["业务应用流水线"]
  D --> R["Artifact Registry"]
  P --> S["Skill Registry"]
  S --> A["idux-cli / API 证据"]
  S --> B["idux-enterprise-design / B 端产品模式"]
  S --> C["idux-style / 视觉基线与样式资产"]
  A --> R
  B --> R
  C --> R
  R --> V["统一验证报告"]
  V -->|"通过"| X["隔离预览 / 导出 / 发布"]
  V -->|"失败"| F["修复或明确失败"]
```

### Project

`Project` 是用户工作单元，保存名称、状态、`artifactKind` 和对应 `TargetProfile`。类型是路由依据，不从消息内容反复猜测。

### Artifact / Revision

每次成功生成形成不可变 Revision，并携带：

- `ArtifactManifest`：入口、文件清单、产物类型和导出格式。
- `ValidationReport`：所有确定性和运行时门禁的结果。
- 构建产物与可复现源码；业务应用另外保存依赖版本和技能证据。

失败或校验未通过的草稿不进入版本历史。

### Artifact Registry

每种产物通过 Adapter 提供目标配置、Manifest、确定性校验和导出命名。新增产物类型时必须先实现 Adapter，不在路由或 UI 中堆叠特例。

### Skill Registry

技能位于 `server/skills/<skill-id>`。Registry 校验 `SKILL.md` frontmatter 与 `skill.config.json`，并依据 `artifactKinds` 精确匹配产物。技能命令通过无 shell 的白名单执行器运行，限制工作目录、环境变量、超时和输出大小。

业务应用使用职责不同的三个运行时技能：

- `idux-cli` 提供与目标版本一致的 props、slots、events、methods 和 demo 证据，不负责决定页面视觉。
- `idux-enterprise-design` 深度参考 Cloudscape 的任务与资源管理模式，将其抽象为通用 B 端信息架构、Dashboard/集合/详情/创建编辑/工作流模式、操作作用域、状态覆盖、响应式优先级和 Loop 质量合同；只使用语义规则，不引入 Cloudscape React 实现，也不假设云计算领域。
- `idux-style` 保存 IDux 视觉基线、主题与应用壳 CSS、设计令牌和视口样式资产，不执行命令，也不决定业务页面模式。

业务应用先形成 `RequirementContract`，再根据当前 `ApplicationBlueprint` 生成增量 `ChangePlan`。蓝图 v3 为每个视图结构化记录页面模式、密度、内容宽度、响应式优先级、数据状态与集合策略，为每个动作记录全局/上下文/批量作用域和可验证结果。生成器只编排规划、三类 Skill 证据、Schema 驱动运行时和可追溯产物；领域模型、需求分析、规划、渲染、验证和修复分别独立。运行时固定采用多文件职责边界：`App.vue` 只装配 Provider 与根壳，`IxProLayout` 应用壳、视图组件、`IxModal` 危险操作确认和状态控制器分别生成。固定列表模板、`spec.ts` 和 `style-kit.ts` 已移除。

需求存在会改变范围、核心流程、数据、权限或安全结果的歧义时，Loop 每轮只挂起并询问一个问题。回答作为结构化决策写入项目状态，恢复后重新分析；可能继续询问下一个阻断问题，直到契约为 `ready` 才能规划和生成。

### 业务应用参考图生成

业务应用与大屏一样支持参考图驱动，但不能把图片直接交给任意代码生成器。受控链路为：

```mermaid
flowchart LR
  I["参考图 + 文字需求"] --> C["模型视觉能力检查"]
  C -->|"不支持"| B["明确失败，不静默忽略图片"]
  C -->|"支持"| A["原图 + 局部裁剪分析"]
  A --> S["结构化呈现证据"]
  S --> P["需求契约 + 应用蓝图 + 变更计划"]
  P --> E["B 端模式 + idux-cli API 证据 + idux-style 资产"]
  E --> G["受控模板或受约束源码候选"]
  G --> V["1920 / 1366 任务场景 + 862 嵌入滚动 + 截图"]
  V --> R["页面模式、状态覆盖、参考图与多视口复核"]
```

文字需求与澄清决策决定业务对象和任务，参考图决定应用壳、导航方向、视图类型、内容密度、表面层级和组件角色。图片分析器支持概览、列表、表单、详情、工作流和领域定制视图；不可辨认或缺少关键业务边界时明确记录未知并逐轮澄清。导出证据只保存图片哈希和分析哈希，不保存图片本体或原始视觉清单。

业务应用 Loop 会持久化需求决策、需求契约、应用蓝图、变更计划、JSON-safe 图检查点、未完成候选、失败原因、已经尝试的策略和显式修复终止状态。“继续”只在仍有自主策略时恢复同一目标，不能从策略数量猜测是否耗尽。样式/配置失败先走确定性修复，局部渲染失败允许受约束源码修复；页面模式、信息架构或状态覆盖失败直接进入目标模块重规划，再进入证据扩展重规划。每轮都重跑需求追踪、静态安全、生产构建、多视口任务场景、网络和视觉门禁，只有自主策略全部复检失败时才进入人工选择。

## 三条不可降级的质量线

### 准确性

- 结构化意图路由：明确的普通表格、管理列表进入 `business-app`；大屏需求进入 `dashboard`；模糊需求先澄清。
- 真实数据与模型生成代码分离保存，模型只看到必要的数据形状；预览响应时才安全内联事实数据。
- IDux Components、CDK 与 Pro 依赖使用同一精确版本，保存版本、上游提交和证据哈希；模型可生成受约束页面规格或批准目录内的源码候选，但候选不能绕过模块化源码、ProLayout、模态确认、静态安全、构建、网络、双视口和任务场景门禁。
- 每个 Revision 必须有 Manifest 和通过的 ValidationReport，发布端再次执行门禁。

### 体验性

- 首页显式选择“大屏”或“业务应用”，卡片和工作台持续展示类型，避免生成结果与预期不一致。
- 工作台按产物语义预览：数据大屏缩放固定画布，业务应用占满真实工作区响应式渲染；业务应用根节点不得超出 iframe，ProLayout 内容区是唯一纵向滚动容器，并额外通过嵌入式窄视口结构门禁。完整任务验收视口与交互预览彼此独立。
- 数据大屏保留实时局部预览、阶段状态、问题修复和断源处置；业务应用分别在 1920×1080 和 1366×768 独立执行每条需求场景，包括导航、创建、详情、编辑、状态流转、确认、删除和结果断言，不再用“按钮出现反馈”代替业务闭环。
- 会话中的状态询问不得写入业务需求；澄清决策按当前需求作用域和问题主题去重，旧需求回答不得跨轮污染。失败策略耗尽后，同一 `flowVersion` 最多允许基于已确认契约重新生成一次；再次失败必须进入终止态，不再推荐相同输入重跑。
- 回退复制完整多文件产物，不修改历史版本；业务应用导出提供可复现源码 ZIP。

### 安全性

- 生成代码不能直接执行任意命令；业务应用源文件、导入、运行时 API、构建目录和输出大小均有白名单。
- 预览运行在独立 origin 和 sandbox iframe 中；响应使用严格 CSP，`connect-src 'none'`，禁止表单、跳转、对象和子框架。
- Dashboard 仅可声明 `fetch('./data.json')` 作为离线回退；其他网络 API 在进入版本前失败。预览时数据已内联，因此不会产生网络读取。
- 模型、MCP 和发布密钥在 API 返回与持久化前统一遮罩/恢复；本地敏感文件使用受限权限和原子写入。
- 发布只接受验证通过的 Revision；配置缺失或资产不可信时明确失败，不生成伪发布地址。

## 扩展规则

新增产物类型必须同时交付：

1. `ArtifactKind`、TargetProfile 和 Adapter。
2. 明确的意图规则与创建时类型确认。
3. 受控生成器或技能，以及权限和依赖证据。
4. 确定性校验、真实浏览器运行校验和失败处理。
5. 隔离预览、可复现导出、发布前复检和安全审计。
6. 覆盖正确路由、生成、回退、重启恢复和越权失败的端到端测试。

任何新增能力不能绕过 Registry、ValidationReport 或隔离预览直接交付产物。
